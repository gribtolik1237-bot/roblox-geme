## 5. Как тестировать (уроки)
- Логику проверять временным Script `ZZ_*` в ServerScriptService (печатать `[TEST] ...`, читать `get_console_output`, УДАЛЯТЬ после). `require` из `execute_luau` даёт ОТДЕЛЬНЫЙ экземпляр модуля; внутри Play временный Script в ServerScriptService получает те же живые экземпляры.
- Запекание мира в Edit (Hall, Shops, PlotService.BuildWorld): клонировать модуль и его изменённые зависимости рядом (`ZZ_*`), подменить пути в `Source` клона (`gsub`), вызвать `Build(true)`/`BuildWorld(true)`, удалить клоны. `execute_luau` может писать `Script.Source` (удобно для перезаписи модулей целиком).
- Мультиплеер: Test → Start Test Session → «Server and Clients», затем в окне Server: Test → Add Clients (по одному клиенту). Каждое окно — свой `studio_id` (Server/Client DataModel): серверные проверки `execute_luau(Server)`, клиентские `execute_luau(Client)` + `Net.invoke`. Тестовые игроки: id -1, -2, ... (новый клиент = новый id). Закрыть окна: PowerShell `CloseMainWindow` для процессов кроме основного.
- Ввод в Play: `user_mouse_input` по `instance_path`, `user_keyboard_input` (E на ProximityPrompt срабатывает, когда подсказка в кадре). В эмуляторе телефона синтетическая мышь НЕ нажимает кнопки (нужен реальный тач).
- Запись в DataStore из Edit запрещена — только из плейтеста.
