## 4. Как работать со Studio (уроки)
- Код и мир живут ВНУТРИ места (без Rojo); `place/` — выгрузка скриптов. Правка файла в `place/` в игру не попадает — правь в Studio (`multi_edit`/`execute_luau`), сохраняй `save_place` (не во время Play), потом выгрузка: `node tools/export-place.cjs --mcp "<путь к StudioMCP.exe>"` + `node tools/verify-export.cjs` (подробно `place/EXPORT_STATUS.md`). Если ответ execute_luau огромный — он сохраняется в файл, разбирай Python-ом локально.
- Тесты «нового игрока»: атрибут `ServerStorage.DevFreshProfile = true` (профиль в памяти, ничего не сохраняется), после — false. Временные скрипты `ZZ_*` удалять. `require` из execute_luau = отдельный экземпляр модуля; для живых сервисов в Play — временный Script `ZZ_*`.
- `screen_capture` не рисует Beam/BillboardGui/Highlight и часть SurfaceGui — смотри настоящий экран (computer-use, Roblox Studio разрешён). Камера через `camera_position`/`look_at_position`. Окно Studio вперёд — PowerShell ShowWindow/SetForegroundWindow по процессу с «Лаборатория» в заголовке.
- При входе на моём профиле открывается «Daily Gift» — закрывай Close (не забирай за меня).
- После правки большого модуля — require клона и сборка всех 27 моделей (ловит синтаксис). Комментарий `--` внутри табличной строки съедает остаток строки — используй `--[[ ]]`. Функции для замыканий объявляй выше или forward-объявлением.
- Device Simulator: `StudioDeviceSimulatorService` (`GetDeviceListAsync`/`GetDeviceInfoAsync`, устройство ставить ДО Play, `StopSimulationAsync` после). `Lighting.Technology` скриптам MCP недоступна — смотреть в Properties.
