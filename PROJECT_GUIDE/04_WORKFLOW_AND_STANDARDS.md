# 04. Порядок работы, контроль качества и стандарты

## Цикл каждой задачи (Reflexion loop)
Чекпоинты начальника — только для арта, UI, моделей, света и игровой логики; правка одних документов их не требует (кроме изменения правил работы — тогда проверка согласованности). Повторное ревью — одно, не бесконечный цикл.
0. Перед задачей — прочитать LESSONS LEARNED в `../CLAUDE.md` и нужный узел `../docs/DEVELOPMENT_TREE.md`.
1. Маленький законченный шаг: 1 система / 1 экран UI / 1 образец модели / 1 пакет звуков. Никаких `-- TODO: потом`.
2. **Чекпоинт 1 (каркас/дизайн/визуал)**: сделан образец (экран, модель, свет) → ревью начальником ДО продолжения.
3. **Чекпоинт 2 (финал в Studio)**: логика + VFX + звук подключены, консоль Studio чистая (`get_console_output`), свежие кадры → ревью начальником.
4. Отказ начальника (FIX) → сам сформулировать первопричину («где ошибся, какое правило нарушил») → исправить → записать урок 1–2 строками в LESSONS LEARNED (объединяя дубли) → повторное точечное ревью.
5. Владельцу сдаётся только после ACCEPT. Непроверенное честно помечается NOT TESTED.
6. Коммит + push после каждого завершённого этапа (`../claude/README.md`).

**Начальник** — `trap-lab-chief` (`../.claude/agents/trap-lab-chief.md`, Sonnet 5.5, только Read/Grep/Glob). Ему передают repo_root, ID узлов, требования, изменённые файлы, свежие кадры, 1–2 референса, результаты тестов. Процедура — `../docs/QUALITY_REVIEW.md`.
**Codex без субагента**: делает те же два чекпоинта как самопроверку по чек-листу ниже и QUALITY_REVIEW.md, записывает вердикт и непроверенное в отчёт задачи.

## Короткий чек-лист самопроверки (для Codex и для Claude перед вызовом начальника)
1. Силуэт и пропорции относительно аватара (кадр из игры, не только рендер).
2. Палитра и роли цветов по эталонам; дерево только там, где подходит объекту (решение владельца 2026-11-18); нет неоновых полос по всему.
3. Масштаб, пивот, объект стоит на полу; коллизии совпадают с видимой опасностью.
4. UI: читается на телефоне, не перекрывает, окно модальное, текст не мельче ~11 px.
5. Консоль Studio без ошибок; изменённый remote проверяет типы и лимит.
6. Что не проверено — записано как NOT TESTED.

## 10 стандартов качества (адаптированы под TRAP LAB; правила владельца из 01_GAME.md важнее)
1. **Геймдизайн и первые 60 с**: опора на docs/ и references/; без стен текста; новичка ведут стрелки (уже есть GuideController + стартовая трасса), первая награда за 15–30 с. Боты-заполнители — только по решению владельца.
2. **3D**: чёткий силуэт, фаски, многосоставная форма (не 2–3 голых параллелепипеда); < 10 000 tris (оптимально 500–4 000); саб-меши по материалам; масштаб по аватару (R15 ~5 стад; в лобби аватар x2); пивот, стоит на полу; декор: Anchored, CanCollide/CanTouch/CanQuery = false, CollisionFidelity Box; коллизионные — Hull/PreciseConvexDecomposition. Дерево допустимо там, где соответствует объекту и референсу.
3. **Свет**: контраст света/тени, Atmosphere, Bloom, SunRays, ColorCorrection по эталонам — у TRAP LAB яркий дневной «игрушечный» вид; Technology проверять вручную в Properties.
4. **Game feel/VFX**: каждое действие = анимация + звук + частицы `:Emit(N)` + отклик камеры/числа; пружины для инерции; hit-stop и вспышки для сильных ударов; эффекты к Attachment, очистка через Debris.
5. **UI**: палитра 60/30/10 по референсам, шрифты Fredoka/BuilderSans, ResetOnSpawn=false, ZIndexBehavior=Sibling; адаптивность ПК/телефон/планшет (UIKit.scaleFor); скруглённые бары в CanvasGroup; UIStroke без артефактов; ScrollingFrame с AutomaticCanvasSize; тактильные кнопки (hover 1.04/press 0.94 + звук).
6. **Звук**: слои sub/mid/transient, ADSR, награды — восходящий питч, ошибки — нисходящий; мастеринг (LPF < 12 кГц, микрофейды, -6 dB); SoundGroup-иерархия, 3D-звуки с InverseTapered, пул вариаций + PlaybackSpeed 0.92–1.08, ducking, единый реестр, PreloadAsync. (numpy/ffmpeg на ПК не установлены — для синтеза есть `../assets/make_sfx.py`.)
7. **Ввод**: каждое действие — ПК, тач-кнопки, геймпад (ContextActionService), как у стройки.
8. **Безопасность**: не доверять клиенту; rate limit на всех remotes (`Balance.RateLimits`); проверка состояния, кулдауна, дистанции, владения.
9. **Данные/монетизация**: сессионный кэш, pcall + ретраи, автосейв, BindToClose, анти-дюп; идемпотентный ProcessReceipt.
10. **Чистый Luau**: модули, `--!strict` где возможно, современное API (task.*, workspace:Raycast); подписки и циклы очищать (Janitor/Trove или явный Disconnect); коммит после ACCEPT.

## 3D через Blender MCP (приоритет)
- Модели создаются в живой сцене Blender через MCP (`execute_blender_code`: bpy, Bevel/Mirror/Subdivision/Decimate, разделение по материалам). Headless CLI — запасной путь (`C:\Program Files\Blender Foundation\Blender 5.2\blender.exe -b --factory-startup -P script.py`).
- Перед экспортом: рендер/скрин вьюпорта с 2–3 ракурсов рядом с кубом-эталоном высоты R15 → начальнику. «Коробка», кривые пропорции, артефакты шейдинга → переделать до экспорта.
- Экспорт `.fbx` (Scale 0.01, Apply Transform) в `../assets/models/`, затем импорт в Studio и финальный кадр в игре (Blender-рендер не подтверждает вид в Roblox). Подробно — `../docs/ART_WORKFLOW.md`.
- На Шаге 0 каждого чата: проверить Studio MCP (`list_roblox_studios`, консоль); в 3D-задачах также Blender MCP (сцена, единицы, объекты). Blender не отвечает → попросить владельца запустить MCP-аддон в Blender.

## Инструменты на ПК (2026-11-18)
Есть: git, gh (вход gribtolik1237-bot), node, python 3.13, Blender 5.2 (MCP-аддон + CLI), Roblox Studio MCP. Нет: rojo, argon, ffmpeg, numpy/scipy. Ничего не устанавливать без просьбы владельца.

## Экономия лимита
Не выводить в чат большие куски кода; не читать целиком огромные файлы и бинарники; батчить однотипное (один скрипт на пакет моделей/звуков); владельцу — кратко. Остановиться с запасом (сохранить ≥10 % пятичасового лимита на сохранение и push).
