# Для ассистента (Claude): как работать с этим репозиторием

Владелец создал этот репозиторий (2026-11-17), чтобы вся работа по TRAP LAB хранилась здесь и ничего не терялось между чатами.

## В начале каждого чата
Сначала прочитать `docs/DEVELOPMENT_TREE.md` и корневой `CLAUDE.md`. Это компактная карта текущей работы и порядок вызова `trap-lab-chief`. Для конкретной задачи читать относящиеся к ней документы и память. Перед приёмкой следовать `docs/QUALITY_REVIEW.md`.

1. `git pull` в локальном клоне `C:\Users\yarik\AppData\Local\Roblox\roblox-geme`.
2. Прочитать `claude/memory/MEMORY.md` и все файлы памяти, затем `docs/HANDOFF.md` (последний раздел) и самый свежий `docs/NEXT_CHAT_PROMPT_S*.md`.
3. Studio: `list_roblox_studios` → место «Лаборатория ловушек».

## В конце работы (и после каждой крупной части)
1. Обновить документы в `docs/` (HANDOFF, TASKS, TESTING_REPORT, отчёт сессии), при необходимости — память в `claude/memory/` (и в локальной папке памяти Claude).
2. Выгрузить скрипты места в `place/` (см. ниже), чтобы код в репозитории совпадал с местом.
3. Владелец повторно явно разрешил автоматические commit/push 2026-11-17. После завершённой связанной порции просмотреть `git status` и diff, добавить конкретные относящиеся к задаче пути, создать содержательный коммит и выполнить push. Коммитить с адресом `301790371+gribtolik1237-bot@users.noreply.github.com`. Сохранить исходники Blender, используемые карты/экспорт и обновления ASSET_REGISTRY, если менялись ассеты. Временные work/ и посторонние изменения не включать. Непроверенный остаток честно указывать в документах.
4. После push проверить совпадение локального HEAD с удалённой веткой. При временной сетевой ошибке повторить, при расхождении сначала fetch и разобрать изменения, сохранив обе стороны. Force-push в обычном процессе не использовать. При конфликте или недоступной авторизации сохранить локальный коммит и сообщить точную причину. Состояние «сохранено на GitHub» подтверждается успешным push и сверкой.

## Выгрузка скриптов места в `place/`
Основной проверенный способ — `node tools/export-place.cjs --mcp "<актуальный путь к StudioMCP.exe>"`, затем `node tools/verify-export.cjs`. Он напрямую читает Edit datamodel, сверяет состав и суммы, пишет EXPORT_MANIFEST. Сначала проверить, что локальный diff place/ не содержит ещё не перенесённых в Studio правок; сохранить такие изменения перед экспортом. При изменении Studio во время выгрузки повторить после стабилизации. Обновить EXPORT_STATUS и дерево. Подробности в place/EXPORT_STATUS.md.

Прежний альтернативный способ через HTTP описан ниже для истории.
Код живёт внутри места Studio. Способ без расхода контекста: временный локальный приёмник (`python -I recv.py <repo>/place`, 127.0.0.1:8765) + `execute_luau` в Studio шлёт каждый скрипт `HttpService:PostAsync`. Нужен адрес `127.0.0.1` в HTTP-allowlist ассистента Studio (Assistant Settings → MCP Permissions) — это делает владелец, ассистент настройки безопасности сам не меняет.
Имена файлов: путь по дереву Studio, суффикс `.server.luau` (Script), `.client.luau` (LocalScript), `.luau` (ModuleScript).
